# 动效 motion · 规范（条目化索引）

> 权威源：原体系 `animation.md`（入场生长的方向与缓动以原文为准；**时长一处偏差**——原文按生长占比分两档，
> 本仓库统一 480ms，理由见下方偏差 1。另记四处补充）。
> 本页职责：给每条规则一个稳定 ID + 指向实现位置，供代码注释回引与修订检索。
> 适用范围：**通用动效**——入场生长动效与播放时机，跨图表共享。图表专属动效（如数值滚动、
> 展开折叠、下钻切换）由各图表规范页自行定义并覆盖本页默认，本页不预写。
> 分层：缓动与逐帧循环是 **L1 构件**（`core/motion.js`，零 DOM 纯逻辑），
> **逐帧重绘由图元渲染器提供**（`core/mark.js` 的 `renderBars` / `renderLine` 返回 `draw(t)` 闭包），
> **播放时机由 L2 判定**（`charts/cartesian/index.js`）。
>
> **交互态无过渡动画不在本页复述**——tooltip / 指示线 / 轴贴片的「瞬移跟随、不淡入淡出」权威定义在
> [tooltip.md](tooltip.md) TOOLTIP-05④ / TOOLTIP-10（「规范只有一个家」，WORKFLOW §一）。
> 本页只管**入场**：动效的适用面是图元第一次出现，不是交互反馈。
>
> **⚠️ 关于铁律4（组件 API 不暴露样式参数）**：本组件给 API 加了 `animation` 布尔开关（MOTION-07），
> 这是**语义配置而非样式参数**——它决定「要不要有入场行为」，与 `dataLabel` / `zoom` / `axisTitle` 同类；
> 而「多快、什么曲线」才是样式，它们分别留在值 token（MOTION-02）与规范值常量（MOTION-03）里，
> API 一概不收。宿主页面存在合理的关闭诉求（打印 / 截图 / 首屏批量渲染 / 嵌入报告），
> 这些场景改 token 关不掉（token 是主题级、不是实例级）。

## 入场生长

| ID | 规则 | 实现 | 状态 |
|---|---|---|---|
| MOTION-01 | **图元入场即生长**，方向按图表类型固定：<br>· **柱**：竖向长高，**从零基线长出**——正值向上、负值向下（0 恒落在某条分割线上，SCALE-01 保证起点稳定）；0 值占位柱（`size-zero-bar-placeholder`）同步长出<br>· **折线**：横向拉线，**自左向右**；渐变面积（`dv-line-area`）、堆叠填充带（`dv-line-stack-fill`）与数据点跟随同一条生长前沿——点在前沿扫过其类目中心时出现<br>**边界**：生长的是图元几何本身，不是不透明度——**没有淡入**。折柱组合里柱与线各按自己的方向同时生长，共用同一时长（MOTION-02） | `core/mark.js` → `renderBars()` / `renderLine()` 返回的 `draw(t)`；`charts/cartesian/index.js`（收集与驱动） | ✅ |
| MOTION-06 | **堆叠柱整根从零基线一起长**，不逐段接力：值空间里段的两端 `base` 与 `base + v` **同乘进度 t**，于是整根堆叠柱作为一个实心柱从 0 轴升起、段比例全程正确、段间无缝。归一化堆叠（`stack: 'percent'`）同理。<br>**为什么不逐段接力**：段数由数据决定（2～6 段不等），接力会让每段只分到几十毫秒、观感偏碎，且**段数变化时节奏不一致**——同一页并排的两张堆叠图会快慢不同，违背「视觉节奏统一」。<br>**堆叠折线**同此口径（其值已在 L2 累加为绝对值，横向生长不受影响） | `core/mark.js` → `renderBars()` 返回的 `draw(t)` | ✅ |

## 时长与缓动

| ID | 规则 | 实现 | 状态 |
|---|---|---|---|
| MOTION-02 | **时长统一 480ms**（`motion-duration-grow`，三主题同值），**不按图表类型 / 数据 / 生长占比分档**。<br>**一张图只有一个时长，全站也只有一个时长**：同一页并排的任意两张图同时起跑、同时到达，节奏完全一致；折柱组合里柱竖向长高与线横向拉线也在同一时刻收束。<br>**新图表接入无需登记任何东西**——横向条形 / 饼环 / K 线只要把自己的 `draw(t)` 交给同一个 `runGrowth`，时长自动一致。<br>**偏离源规范的「按生长占比两档（0–50% → 320ms / 51–100% → 480ms）」**，理由与实测依据见下方偏差 1 | `charts/cartesian/index.js`（读 `--motion-duration-grow` 传给 `runGrowth`）；`tokens/*.json §23` | ✅ |
| MOTION-03 | **缓动统一 `cubicOut`** = easeOutCubic = `cubic-bezier(0.33, 1, 0.68, 1)`（先快后慢、自然减速），全部生长动效同一条曲线，不按图表 / 主题分化。<br>跨端实现**以贝塞尔函数为准**：本仓库自研逐帧补间，用等价闭式 `1 - (1 - t)³`；若将来某处改用 CSS / ECharts 驱动，分别写 `cubic-bezier(0.33, 1, 0.68, 1)` 与 `animationEasing: 'cubicOut'`，三者视觉一致。<br>曲线系数是**规范值常量**（三主题同值、不参与主题分化，同 `Y_SPLIT_LINES` 与 line.md「点数 > 13」的先例），故写在 `core/motion.js` 而非 token——`cubic-bezier(…)` 无法被 `tokenNum` 解析成逐帧补间需要的数值系数 | `core/motion.js` → `EASE_GROW` / `easeOutCubic()` | ✅ |

## 播放时机

| ID | 规则 | 实现 | 状态 |
|---|---|---|---|
| MOTION-04 | **只在图表实例首次挂载时播一次**。此后同一实例内的任何重绘一律**瞬时出图、不重放**：<br>· **容器 resize**（`observeResize` → `build()`）——拖拽改尺寸时重放会持续抖动<br>· **图例显隐**（LEGEND-06）——点一次图例让没变化的系列也重长一遍，是噪音不是反馈<br>· **缩放轴拖动**（DATAZOOM-07）——拖手柄期间 `build()` 逐帧触发，重放等于每帧重启动画<br><br>**「重新出现」靠重建实例**：销毁后重新 `CartesianChart(host, cfg)` 即新实例、重新播放。切主题 / 切示例 / 改配置本就走 destroy + 新建（WORKFLOW §六：切主题必须触发 L2 重绘），故这些场景天然重播，无需额外 API。<br>**动画期间被打断**（如动画未完就拖缩放轴）：立即取消并直接落终态，不做半途回退 | `charts/cartesian/index.js`（闭包内 `firstBuild` 标记 + `stopGrow` 收口） | ✅ |

## 参与范围

| ID | 规则 | 实现 | 状态 |
|---|---|---|---|
| MOTION-05 | **只有数据图元生长，坐标系与附属元素直接就位**——网格线、Y/X 轴标签、轴标题、图例、缩放轴、水印在第 0 帧即为终态，不生长也不淡入。理由：它们是**图元赖以被读懂的参照系**，参照系自己动起来会让生长中的柱线失去度量基准。<br>**数据标签是唯一例外的特殊处理：生长期间整层隐藏，动画结束后出现**（不淡入）。标签锚点绑在柱顶 / 数据点上，若逐帧跟随需要每帧重跑文本测量（`measureTexts`）与碰撞过滤（`dropCollisions` / `dropOversized`），既掉帧、又会在生长过程中反复「放不下 ↔ 放得下」而闪烁；若不跟随则数字先悬在空中等柱子长上来，更怪。<br>**hover 全链路生长期间即时可用**（不等动画结束再接线）：tooltip 显示的是**数据真值**，与动画进度无关——为 480ms 的观感牺牲交互响应不划算。指示线 / 轴贴片同理，其「无过渡」由 TOOLTIP-10 管辖 | `charts/cartesian/index.js`（标签层显隐 + 生长驱动的调用位置） | ✅ |

## 与原体系文档的偏差（本仓库取值）

1. **时长不分档，统一取 480ms**（MOTION-02）。原文按「生长占比」分两档：0–50% → 320ms、51–100% → 480ms。
   本仓库**只取长档**。依据是把现有 11 个示例 × 3 档数据量共 33 种组合全部算过一遍——**只有 2 种落进短档**：

   | 组合 | 生长占比 | 原规则档位 |
   |---|---|---|
   | `基础柱状图` · 数据量「中」/「多」 | 0.495 / 0.455 | 320ms |
   | `基础柱状图` · 数据量「少」 | 0.867 | 480ms |
   | `正负堆叠` · 少 / 中 / 多 | 0.566 / 0.566 / 0.628 | 480ms |
   | `归一化堆叠` · 任意 | 1.000 | 480ms |
   | 纯折线 · 少 / 中 / 多 | 0.750 / 0.938 / 0.972 | 480ms |
   | 分组柱 / 堆叠 / 折柱组合 · 任意 | 0.784 – 1.000 | 480ms |

   根因是 [axes.md](axes.md) SCALE-03 的刻度算法做**占比最大化**（`INTERVAL_STEPS` 最大相邻档位比 1.33
   ⇒ 正值场景占比下限约 75%），而纯折线的水平跨度恒为绘图区宽 ×(n−1)/n（`bandX` 两种 mode 的 step 都是 W/n），
   n ≥ 3 即恒 > 50%。**在本仓库的刻度体系下，分档规则几乎恒定输出长档**——它带来一整套占比口径
   （柱按值域、线按宽度、双 Y 各按自己的轴、折柱组合取较大者）却几乎换不到可感知的差别，
   反而让「同一页两张图快慢不同」成为可能，与源规范自己写的「保持视觉节奏统一」相抵触。
   故取消分档，统一 480ms：规则更简单、节奏绝对一致、新图表接入零成本。
   **改回两档的代价也很低**——恢复 `growthRatio()` / `growDuration()` 两个纯函数 + 拆回两个 token 即可，
   口径表见本条上方（本仓库曾实现并实测：少 475ms、中 316ms、多 305ms，与分档规则一致）。

2. **补齐堆叠口径**（MOTION-06）：原文只写「柱状图 · 竖向长高 · 主图**高度**占满高的比例」，未区分单柱与堆叠。
   本仓库已有普通堆叠 / 正负堆叠 / 归一化堆叠三种形态（[bar.md](bar.md) BAR-05/06），必须定口径，取「整根一起长」。
3. **补齐播放时机**（MOTION-04）：原文只定义了「入场」，未说明何为一次入场。本仓库的 `build()` 被 resize、
   图例显隐、缩放轴拖动共用且每次整树重建，不定这条规则的话拖一次缩放轴滑块会每帧重放整套动画。
4. **补齐参与范围**（MOTION-05）：原文未列举哪些元素参与生长。数据标签的处理是本仓库特有问题——
   原体系文档中数据标签与动效分属两份文件、未交叉定义。
5. **补齐降级与开关**（MOTION-07）：原文未提无障碍降级，也未提关闭通道。

## 活 demo

`playground/cartesian-preview.html` 与 `index.html` 的 **动效** 旋钮（`animation` 开 / 关）：

- **关**：三主题与不带动效时逐像素一致——零回归的验收点（MOTION-07）。
- **开**（默认）：卡片首次渲染即播。playground 的 **重播** 按钮销毁并重建当前卡片，可反复观察
  （切主题 / 切示例 / 动任意旋钮同样是重建，都会重播——这正是 MOTION-04 的表现）。
- **时长处处一致**（MOTION-02）：切任意示例、任意数据量、任意主题，动画都是 480ms——
  三主题横排时最直观：三张卡同时起跑、同时收束，没有哪张先到。切数据量（少 / 中 / 多）也不改变节奏。
- **生长方向**：`基础柱状图` 柱从 0 轴向上长；`正负堆叠` 负向柱向下长、与正向柱同时到位；
  `基础折线` 自左向右拉线，数据点被前沿扫过时逐个出现；`折柱组合 · 双 Y` 柱竖向、线横向**同时**进行且同时结束。
- **堆叠整根一起长**（MOTION-06）：`普通堆叠` / `归一化堆叠` 全程段比例正确、段间无缝，
  不是下段长完上段再长；`归一化堆叠` 因总高恒定，观感是整列等比升起。
- **不重放的三种重绘**（MOTION-04，核心验收点）：拖缩放轴手柄全程无重放、点图例显隐瞬时、
  拖拽卡片改尺寸瞬时——这三处任何一处出现重放都是缺陷。
- **数据标签**（MOTION-05）：开数据标签的示例（`基础柱状图` / `基础折线`）生长期间无标签，结束瞬间出现。
- **无障碍降级**：系统开启「减弱动态效果」（macOS 辅助功能 → 显示 → 减弱动态效果）后，开着旋钮也直接出终态。

## Do / Don't

- ✅ **Do**：改时长 = 改 `tokens/*.json §23` 的 `motion-duration-grow`（三主题同步，合同校验会拦）；
  新骨架（横向条形 / 饼环 / K 线）接入 = 让渲染器返回 `draw(t)`，交给同一个 `runGrowth`，时长自动一致；
  逐帧回调里只重写几何属性。
- ❌ **Don't**：把 token 读取（`tokenNum` → `getComputedStyle`）或 `<defs>` 创建放进逐帧回调
  （前者每帧触发样式重算、后者每帧泄漏一个渐变节点）；用 `transform: scaleY()` 生长柱子
  （会把 `radius-bar-top` 圆角压扁，THS 可见）；给 API 加时长 / 缓动 / 延迟参数（样式走 token 与规范值常量）；
  给 tooltip / 指示线 / 图例弱化加过渡动画（TOOLTIP-10 明令无过渡）；让坐标系或轴标题参与生长；
  按图表类型 / 数据规模给某类图单独调时长（统一是 MOTION-02 的核心，要改就整体改 token）。

## API

`CartesianChart(host, { animation })` —— 布尔，缺省 `true`。
`false` 时直接出终态；`prefers-reduced-motion: reduce` 下无论传什么都直接出终态。
时长与缓动不接受配置（分别见 MOTION-02 的 token 与 MOTION-03 的规范值常量）。
