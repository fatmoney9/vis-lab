# 饼图 / 环形图 · 规范（条目化索引）

> 本页职责：给每条规则一个稳定 ID + 指向实现位置，供代码注释回引与修订检索。
> 适用范围：**无坐标系的占比图**——饼图（实心）与环形图（中空）。两者不按名字分体，而是
> 同一个 `PieChart` 的一个旋钮 `variant`（`'donut'` / `'pie'`），沿用 [bar.md](bar.md) 的先例：
> 变体是取值组合，不是两份组件。
> 分层：本族**新开一套 L2 骨架**（`charts/charts/pie/`），与 `CartesianChart` 平级、互不依赖——
> 它没有类目轴、没有值域刻度、没有网格，`scale` / `grid` / `axis` / `datazoom` / `crosshair`
> 整条 L1 链路都不适用；但**通用构件全部原样复用**：图例、数据标签、tooltip、水印、取色、
> 格式化、主题解析、画布骨架。本页只写「扇区自己的规则」，通用规则各回其家：
> 取色 → [color.md](color.md) COLOR-08 · 图例 → [legend.md](legend.md) · 标签 → [data-label.md](data-label.md) ·
> 浮层 → [tooltip.md](tooltip.md) · 动效 → [motion.md](motion.md) · 水印 → [watermark.md](watermark.md)。

## 扇区几何

| ID | 规则 | 实现 | 状态 |
|---|---|---|---|
| PIE-01 | **值 → 角度**：每扇区角 = `v / 可见项之和 × 360°`，**起始 12 点方向、顺时针**。<br>**`null` 与 `≤ 0` 不占角、不画**（与 [bar.md](bar.md) BAR-01「null 跳过」同口径）：占比是「对总量的份额」，负份额没有几何表达；`0` 也**不占位**——柱有 `size-zero-bar-placeholder` 1px 贴基线的表达，扇区的对应物是「0 角度」= 不存在，与 BAR-05 堆叠段「0 不占位」同口径。它们同样不进分母。<br>**绘制序 = 声明序 = 图例序，不按值排序**：排序会让同一实体在数据变化时换色，与 COLOR-04「颜色跟随实体、不跟随排名」直接冲突。<br>扇区间**无间隙**（`padAngle = 0`）、**无圆角** | `charts/charts/pie/geometry.js` → `sliceAngles()`；`charts/charts/pie/index.js` | ✅ |
| PIE-02 | **半径与环宽**：圆心 = 绘图区中心；<br>**外半径 `R = min(--size-donut-radius, min(绘图区宽, 绘图区高) / 2)`** —— token 是上限，空间不足时收缩（同 BAR-03 柱宽「上限 + 放不下就收缩」的口径）；<br>**环宽等比跟随** `ring = --size-donut-ring-width × R / --size-donut-radius`，内半径 `innerR = R − ring`——收缩时保持本主题的环宽:半径比不变，与 BAR-02「柱与间距按同一比例等比缩小」同一先例。**尺寸按主题分化、比值不分化**：THS / iFinD-PC `70 / 28`、Ainvest `80 / 32`，两者的环宽:半径比都是 **0.4**，故等比收缩这条规则跨主题成立、L1 无需知道是哪个主题；<br>**`variant: 'pie'` → `innerR = 0`**（`ring` 不参与，退化为实心饼）；<br>**可用空间**：调用方明确给容器高度时按容器算，未给时用 `--size-donut-container`（三主题当前均 160px 方形）作默认包络，判定口径同 [axes.md](axes.md) GRID-03（`clientHeight >= 40`）。上下结构下还要先扣掉图例占位与间距，剩下的才是环可用的高。<br>**画布 = 图元的外接框，不留任何富余**——「图元」指环**以及圆外的引线与标签带**（PIE-12），无外侧标签时即退化为环的外接方框 `2R`。半径被 token 封顶后，多出来的画布**不会让环变大，只会变成图元与图例之间的死空间**，且随容器尺寸浮动，与 PIE-09「间距恒定」直接冲突。故画布尺寸由图元反推，而不是图元去适应画布。<br>**有外侧标签时**：宽 = `左标签带 + 2R + 右标签带`（带宽由实测文本宽反推，PIE-13）、高 = `2 × max(R, 最外标签的 |y| + 行高/2)`（12 / 6 点方向的标签会探出环外）；圆心因此**不再恒等于画布中心**（`cx = 左带宽 + R`）。<br>两个后果：① 可用空间必须从**图表根元素**量，不能从绘图区量（绘图区已贴着画布，拿它当输入会形成「画布依赖画布」的循环）；② 创建画布时要关掉 `createFrame` 的最小网格高（`minGridHeight: 0`）——那个下限是轴图的可读性兜底，对无轴图只会把画布重新抬高、再造出死空间。<br>**`--size-donut-container` 只是「高度」包络，不约束宽度**：它给的是组件未拿到显式高度时的默认高（口径同 cartesian 的 `size-chart-region-height`），半径由它定；宽度一律由图元反推。故 `容器 ≥ 2×半径 + 标签带` 这条从来不必成立——Ainvest 的 160 vs 2×80 不是冲突，标签带向外长出去即可。<br>饼图不另设尺寸 token，共用 `size-donut-*`（见待办） | `charts/charts/pie/geometry.js` → `donutRadii()`；`tokens/*.json §20` | ✅ |

## 图例布局

| ID | 规则 | 实现 | 状态 |
|---|---|---|---|
| PIE-09 | **饼环支持两种图例布局**，形态定义见 [legend.md](legend.md)——排布方向 LEGEND-01、方位 LEGEND-10、纵列溢出滑动 LEGEND-11；本条只定「支持哪几种、默认哪种、各自怎么配」：<br>· **`legend: 'right'` —— 左右结构（饼与环的共同默认）**：图左、图例右，图例纵向单列从上到下、左对齐，整列与绘图区垂直居中对齐。**默认不因 `variant` 分化**——饼和环都从左右结构起步。<br>· **`legend: 'bottom'` —— 上下结构**：图上、图例下，图例横向**居中**、行宽不足自动换行。<br>**不支持 `top`**：图例在上是直角坐标图的形态（LEGEND-04），饼环的设计源里没有这种排布。<br>**图与图例的间距 = `spacing-legend-chart-gap`（三主题 24px）**，两种结构共用同一个 token；图例朝向图那一侧的容器内边距（`spacing-legend-container-*`）清零，避免与之叠加成双份。**开着外侧标签时这 24px 从标签带外沿量起**，不是从环的外沿——标签带属于图元、已算进画布（PIE-02 / PIE-13），故这条规则不因标签形态而变，量的始终是「画布外沿 → 图例」。<br>**整组居中**：两种结构下绘图区都**不撑满剩余空间**，而是贴着图元的外接框成块（见 PIE-02：无外侧标签时是 `2R` 的正方形，有则加上两侧标签带），「图 + 间距 + 图例」作为一组在容器内居中——撑满的话图例会被推到容器边缘，且中间多出的空白随容器浮动，间距就不恒定了。左右结构把画布宽也显式传给 `createFrame`；上下结构只定高，宽度铺满、图元在其中水平居中即为整体居中（横向富余不夹在图元与图例之间，不影响间距）。<br>**由调用方按场景选**（宽扁卡片走 `right`、窄高卡片走 `bottom`），是「要哪种形态」的语义配置而非样式参数——同 `variant`，尺寸/间距/字号仍全走 token（WORKFLOW 铁律4）。**不进 `behavior.json`**：三主题同一套形态，不是主题分叉。<br>**左右结构下图例纵列的高度上限 = 图元高度 × 2**，超出即在图例区内滑动（消费 [legend.md](legend.md) LEGEND-11 的「纵列溢出可滑动」——那条给的是**行为**，本条给的是**上限**）。不设限时图例会把整张卡片无限撑高（36 扇区能撑到上千像素，而环仍只有 2R），卡片高度就完全由图例说了算，与「图 + 图例相邻成一组」的观感背道而驰。**取比例不取像素**：它跟着图元大小走，换主题、换半径、开不开外侧标签都自洽，故不进 token（同 BAR-03 柱与间距的 2:1）。倍数在 L2 定、上限值写进一个自定义属性交给 CSS 表达；容器另有显式高度时两条约束同时生效、取更紧的那个。<br>**DOM 顺序恒为「绘图区 → 图例」**，方位只由容器 flex 方向切（LEGEND-10）——这与 `CartesianChart` 相反（那边图例 DOM 在前 = 在上），是本族唯一的骨架差异 | `charts/charts/pie/index.js`（DOM 顺序 + `.dv-chart--legend-*` 修饰类 + 推导 `layout`/`align`）；`core/legend.js` → `renderLegend()` 的 `layout` | ✅ |

## 数据标签

| ID | 规则 | 实现 | 状态 |
|---|---|---|---|
| PIE-04 | **扇区内档**（`labelLayout: 'inside'`）——**不是默认形态**，默认走外侧引线档，见 PIE-12。显不显仍由 `dataLabel` 三态定，权威定义在 [data-label.md](data-label.md) LABEL-05（饼环是其「一个类目一个值就出标签」原则的明确例外：占比由扇形本身表达、名称由图例承载）。本条只定**这一档开启后**怎么摆：<br>**文本只出原值**（不带名称——扇区内放不下两段，名称交给图例；外侧档带名称，见 PIE-12）。<br>**锚点** = 扇区中线方向 × **环带中心半径** `rm = (R + innerR) / 2`（`variant:'pie'` 时即 `R / 2`，一条公式两种形态通吃）。<br>**走档②**（LABEL-04）：标签压在扇区填充上，按该扇区色的 WCAG 相对亮度自动切浅底深字 / 深底浅字。<br>**`collide: false`** —— 扇区标签环绕四周、本就不同行，同行碰撞过滤不适用（`core/label.js` 的 `collide` 开关正是为此预留）。<br>**「放不下就不放」由几何判定收口**（LABEL-06③）：`maxWidth = min(rm × Δθ, ring)` —— 取「切向弧长」与「环宽」的较小者，**与扇区落在钟面哪个方向无关**，故对任意角度都成立且偏保守；另外 `ring < --line-height-data-label` 时整层不出。<br>**不套用 LABEL-06① 的「非 null 值 > 5 整体不出」**：那条阈值是按类目宽度定的柱线经验值，对扇区没有对应含义——扇区能不能放下完全是几何问题，由上面一条判。THS 环宽仅 28px，长数值下标签自然大量隐去，属预期（同 LABEL-06③ 对 THS 16px 柱宽的既有说明）。<br>文本走与 tooltip 同一份 `makeFormatter`（LABEL-07 / [format.md](format.md) FORMAT-01）显示**原值**；占比数值见待办 | `charts/charts/pie/geometry.js` → `labelAnchor()`；`charts/charts/pie/index.js`；`core/label.js` → `renderDataLabels` | ✅ |

| PIE-12 | **外侧引线档（`labelLayout: 'outside'`，饼与环的默认形态）**：标签摆在圆外，用引线连回自己的扇区。<br>**与扇区内档互斥、二选一**（`labelLayout` 只有这两个取值，不叠加）；**引线与其标签强绑定**——没有「只出引线」或「只出标签」的形态，故隐藏一个标签必然连它的引线一起隐藏。<br>⚠️ **强绑定要靠「先判后画」落实，不能靠事后补救**：三道丢弃（`null` 值 LABEL-07、纵向重叠 PIE-14、放不下 LABEL-06③）**必须全部在画引线之前执行完**。最后一道尤其容易漏——它天然发生在 `renderDataLabels` 内部，而那时引线早已进 DOM，结果是一条指向空处的线（本组件实测过：Ainvest 出 3 条线只出 2 个字）。故 L2 在预演阶段就调 L1 导出的 `dropOversized` 先判一遍，**判定仍只有一份实现**。<br>**默认取外侧而非扇区内**：设计源的插图画的就是外侧；且本档文本带名称，THS 环宽仅 28px 的扇区内几乎必然被 LABEL-06③ 全判掉，把它作默认等于默认什么都不出。<br>**文本 = 名称 + 原值**（如 `营业收入 1,234`），数值仍走同一份 `makeFormatter`（FORMAT-01）；`null` 不出标签（LABEL-07），连带不出引线。扇区内档只出原值，两档的内容口径不同是有意的——外侧有整条标签带，放得下两段。<br>**引线两段，第二段恒水平**：① **法线段** 自外半径起沿半径向外延伸 `--size-donut-label-line-radial`（THS / iFinD-PC `8px`、**Ainvest `16px`**）到**肘点**；② **横段** 自肘点向该侧水平延伸至文字（长度由 PIE-13 的对齐档决定）。**文字的 y 恒等于肘点的 y**——标签锚在自己扇区的自然角度上、**不做任何纵向位移**（LABEL-01 原样适用），故第二段是严格水平线，这也是「未位移」的可断言证据。<br>**左右分侧**：扇区中线角 `mid < π` 归**右**侧、否则归**左**侧（12 点归右、6 点归左）。<br>**颜色分工（LABEL-09 档③）**：**引线**跟随扇区色（`currentColor`，与扇区同一个色槽）、**文字**走中性 `color-text-primary`。色彩关联由线承担，文字不必重复；理由与「为什么不复用档①」见 [data-label.md](data-label.md) LABEL-09。<br>**层级**：引线画在**扇区自己的 `<g>` 内**——图例 hover 弱化（LEGEND-05）与强调态抬层（PIE-10）因此自动覆盖它，无需第二套接线；且引线起点随扇区外扩逐帧重算（PIE-10 外扩时线不会被扇区盖住半截）。<br>**入场**：引线与标签层一起先藏、扫掠结束后一起出现（强绑定的直接后果，MOTION-05） | `charts/charts/pie/geometry.js` → `leaderElbow()`；`charts/charts/pie/index.js`；`.dv-pie-label-line` | ✅ |

| PIE-13 | **三档对齐（`labelAlign`，仅外侧档生效）**——决定横段多长、文字横向对齐到什么。三档都是**形态语义**、由调用方按场景选，同 `variant` / `legend`（铁律4：尺寸间距字号仍全走 token）。记 `e` = 肘点到圆心的水平距离、`w` = 该标签文本宽、`lateral` = `--size-donut-label-line-lateral`、`gap` = `--spacing-donut-label-gap`（8px）：<br>· **`'anchor'`（默认）· 就近**：横段**定长** `lateral`，文字紧跟末端 `gap` 后起排。同侧标签**互不对齐**，各自贴着自己的引线——最紧凑，也最容易看出哪条线连哪个字。<br>· **`'column'` · 同侧成列**：同侧所有横段末端落在**同一条竖线**上（`max(e) + lateral`），文字内沿贴线（右侧左对齐 / 左侧右对齐）。横段因此长短不一，文字排成整齐一列。<br>· **`'edge'` · 贴边**：文字**外沿**对齐到画布该侧边缘（右侧右对齐 / 左侧左对齐），横段逐条拉长补足。文字外沿齐、内沿参差，与 `column` 恰好相反。<br>**标签带宽**（PIE-02 的画布宽输入，相对 R 的外扩量）：`anchor` 与 `edge` 同为 `max_i(e_i + lateral + gap + w_i) − R`（这是能容下全部文字的最紧带宽，`edge` 正因此得名）；`column` 因末端共线而更宽：`max(e) + lateral + gap + max(w) − R`。<br>**带宽被容器封顶**：容器放不下时带宽截断，各标签的可用宽（`maxWidth`）随之变小，**由 LABEL-06③「放不下就不放」自然逐个丢弃**——L2 只负责把 `maxWidth` 算出来喂给 L1，不自己实现丢弃。<br>⚠️ **带宽向上取整**：带宽正是由文本宽反推的，于是 `maxWidth = R + band − 文字起点` 在实数意义上**恰好等于**该文本宽；而 LABEL-06③ 会**重新测量**同一段文字再比大小，两次浮点运算差 1e-14 就足以把「恰好装得下」翻成 false。取整给出不足 1px 的余量稳稳盖住，顺带让画布落在整像素上。<br>**丢弃后要重算一次带宽**（否则画布会比实际图元宽出一截，与 PIE-02「画布恰好是图元外接框」冲突）；**只需一次、不必迭代**：幸存者满足 `w ≤ R + band − 起点`，重算后 `band' = max(起点 + w) − R ≥ 起点 + w − R`，代回即得 `w ≤ R + band' − 起点`，故第二趟不会再丢人 | `charts/charts/pie/geometry.js` → `alignOutside()`；`charts/charts/pie/index.js` | ✅ |

| PIE-14 | **左右两栏各自判重叠**：外侧标签**重叠即隐藏、不做纵向位移**（LABEL-01 原样适用，饼环不开例外）。<br>**贪心本身不在本页**——它就是 [data-label.md](data-label.md) **LABEL-06②**（相邻净距 < `spacing-data-label-min-gap` 则丢后者、首个恒留、与遍历顺序无关地稳定），只是判定轴从「同一行的 x」换成「同一列的 y」。同一个 `dropCollisions` 两轴共用，L2 **调用**它而不复制。<br>**本条只定饼环专属的那一点**：**左右两侧各自成列、分别判定**——异侧标签一个在圆左一个在圆右，横向隔着整个环，不该参与彼此的净距判定。合并判会让左侧的密集把右侧本可显示的标签一并判掉。<br>各标签的判定盒 = `[y − 行高/2, y + 行高/2]`，y 取扇区中线在肘点处的自然值（PIE-12，未位移）。<br>⚠️ **预期后果：扇区一多，标签会掉得很凶**——中 16 / 多 36 两档下，存活的多半只剩几个靠近 3 点 / 9 点方向、彼此拉得开的扇区。这是「重叠即隐藏」的必然结果、不是缺陷，与 THS 16px 柱宽下堆叠段内标签全隐是同一种预期（LABEL-06③ 的既有说明）。若将来判定太狠，两条路：放宽 `spacing-data-label-min-gap`（牺牲呼吸感），或改为允许纵向位移（那就要给 LABEL-01 开例外了） | `charts/charts/pie/index.js`（分栏后各调一次）；`core/label.js` → `dropCollisions()` | ✅ |

| PIE-11 | **外扩带过渡，不硬切**：强调态的外扩量以 `motion-duration-emphasis`（三主题 200ms）+ `cubicOut`（MOTION-03 同一条曲线）补间。<br>**从当前值补间、不从 0 重来**：快速划过一排扇区时，每个扇区都从它此刻的外扩量接着走，不会先跳回原位再长——故实现上逐扇区记录「当前外扩量」，渲染只读这个数，不读布尔状态。<br>⚠️ **与 `runGrowth` 的打断语义有冲突，接线顺序要紧**：`runGrowth` 的 cancel 是「立即落终态」（MOTION-04 为**一次性入场**定的：被打断即刻到位、不半途回退）。强调态却会被反复打断，若先 cancel 再读当前值，读到的是上一轮的**终点**，新补间从终点起步 = 肉眼可见的硬切。正确顺序：**先读当前值 → cancel → 把被落到终态的量改回打断瞬间 → 从那里补间**。这条不改 L1（入场依赖原语义），在 L2 消化。<br>**重建不补间**：resize / 图例显隐会整树重绘，那是重新出图不是状态切换，选中的扇区应当**已经**是外扩的（外扩量初值直接取目标值）。<br>**时长远短于入场**（480ms）：入场是一次性的叙事，hover 反馈是即时应答，拖到半秒会显得迟钝。<br>[MOTION-07] 系统「减弱动态效果」下时长归零、直接落终态。<br>⚠️ 本条**不与 [tooltip.md](tooltip.md) TOOLTIP-10「无过渡动画」冲突**：那条管的是气泡 / 指示线 / 轴贴片这条浮层链路（瞬移跟随），本条管的是**图元自身的几何**，属 [motion.md](motion.md) 所说「由各图表规范页自行定义的图表专属动效」 | `charts/charts/pie/index.js`（`animateEmphasis` + 逐扇区外扩量）；`core/motion.js` → `runGrowth`；`tokens/*.json §23` | ✅ |

## 活 demo

`index.html` 与 `playground/preview.html` 的 **饼图与环形图** 分组（两个示例：`环形图` / `饼图`）：

- **三主题横排**：**Ainvest 的环明显比 THS / iFinD-PC 大一圈**（半径 80 vs 70、环宽 32 vs 28，PIE-02），
  但三者的环宽:半径比都是 0.4，粗细观感一致；扇区色各走自家色板——
  THS 从 `bar-multi` 首色浅蓝 `#52BBFF` 起、iFinD 24 色盘、Ainvest 8 色盘（COLOR-08）；
  图例 marker 三主题**都是圆点**（与柱状图示例的方块 / 折线短横对照，LEGEND-03）。
- **数据标签默认不出**（LABEL-05 的例外）：饼环**没有独立的「数据标签」旋钮**——
  引线与标签强绑定（PIE-12），「显示但没形态」不是合法状态，故显隐与形态合并成一个
  **标签形态** 三档旋钮：**关（默认）/ 引线 / 扇区内**。「关」什么都不传，走组件默认。
  切「引线」出的是外侧档：文字「名称 + 原值」走中性正文色、引线跟随扇区色（档③ LABEL-09），
  明暗切换时**只有档③ 跟着翻转**、档② 不翻，两者可同屏对照；切「扇区内」回到档②
  （按扇区色反色、只出原值，PIE-04）。两档互斥、绝不同屏。
- **图例方位随形态拨默认值**：切到「引线」时 **图例布局** 自动拨到**上下**——左右结构里右侧标签带
  会把图例推得很远、整组重心偏掉。只是**默认值**，可以手动改回左右（组件的默认方位仍是 `right`，PIE-09 未变）。
- **三档对齐**（PIE-13，**标签对齐** 旋钮，非引线档下**置灰而不隐藏**——藏起来会让
  「哪一档才有对齐可言」变得不可见）：
  「就近」各标签贴各自的引线、同侧不对齐；「成列」同侧横段末端共线、文字排成整齐一列；
  「贴边」文字外沿齐画布边、横段逐条拉长。三档切换时**环的大小和位置会变**——
  `column` 的标签带最宽（末端共线推远了），这是 PIE-02「画布由图元反推」的直观验收点。
  另外量得到的两条：每条引线的**末两段 y 相同**（第二段恒水平 = 没做纵向位移），
  每个标签的 y 与其扇区中线的自然位置逐一相等。
- **重叠即隐藏**（PIE-14）：外侧标签在数据量↑ 时**自上而下逐个消失**，且左右两栏各判各的
  （一侧密集不会牵连另一侧）；与柱线那条「超阈值整体消失」（LABEL-06①）形成对照——
  同一个 `dropCollisions`，一个判行、一个判列。
- **数据量 少 4 / 中 16 / 多 36**：36 扇区压色板循环（THS 7 色循环到第 8 个扇区回到首色）；
  扇区数变化不改变动效节奏（MOTION-02）。开着标签时数据量↑可看它们按环宽 / 弧长逐个隐去（PIE-04）。
- **点图例**：隐藏一个扇区 → 剩余扇区重算闭合 360°，**其余扇区颜色一个都不变**（PIE-03 / COLOR-04 的验收点）；
  hover 图例项 → 其余扇区降到 `opacity-visualization-dim`。
- **hover 扇区**：三主题气泡**都走 follow**（与柱线示例的 THS `side-fixed` / Ainvest `top-anchor` 形成对照，
  这是 TOOLTIP-07 特例的验收点）；无指示线、无轴贴片。
- **入场动效**：顺时针扫掠，与同页柱线卡片**同时起跑同时到达**（MOTION-02）；关掉后与不带动效逐像素一致。
- **图例布局**（PIE-09）：两个示例都不带 `legend`，走组件默认的**左右结构**——
  图与图例相邻成组、**整组水平居中**，间距 24px；环形与饼图默认一致，不因 `variant` 分化。
  playground 右栏 **图例** 旋钮切 `上下` 可看另一种：图上、图例下横向居中换行。
  **图例永远在图之后**（DOM 与视觉都是），没有「图例在上」这一档——那是直角坐标图的形态。
- **旋钮显隐**：本族详情页**不出现**缩放轴 / 轴标题 / 渐变面积开关（`CHART_CAPABILITIES` 未声明），
  **也不出现直角坐标系那个「数据标签」开关**（`dataLabel` 能力本族未声明，显隐归标签形态管），
  只剩标签形态、标签对齐、图例布局与入场动效——这是两个预览面「按能力画旋钮」的验收点。
  反向对照：柱状图详情页有「数据标签」开关，却没有标签形态 / 标签对齐 / 图例布局这三个。
- **拖拽卡片改尺寸**（playground）：半径按 PIE-02 收缩、环宽等比跟随，环宽:半径比全程不变。

## Do / Don't

- ✅ **Do**：改环的尺寸与引线长度 = 改 `tokens/*.json §20` 的 `size-donut-*`（三主题同步，合同校验会拦）；
  改扇区取色 = 改 `tokens/palette.json` 或 [color.md](color.md) COLOR-08，不是给 API 加参数；
  新增的扇区专属几何留在 `charts/charts/pie/geometry.js`（标 `[L2-LOCAL]`）并保持纯函数可单测。
- ❌ **Don't**：把扇区几何下沉 `core/`（只有这一个 L2 用得上，WORKFLOW §三）；
  为「无坐标系图用 follow」给 `behavior.json` 加键（那不是主题分叉，见 PIE-05）；
  按值给扇区排序（COLOR-04）；用半径生长做入场（PIE-06）；
  给 API 加 `startAngle` / `padAngle` / `innerRadius` / 引线长度一类的样式参数（铁律4——
  `variant` / `labelLayout` / `labelAlign` 是形态语义，尺寸走 token）；
  把「放不下就不放」或碰撞贪心复制进 L2（通用规则在 `core/label.js` 内置，
  L2 只给 `maxWidth` 与分好栏的盒子，**换个轴也是调用不是复制**，LABEL-06②）；
  为让外侧标签排得下而上下推挤它们（PIE-14 / LABEL-01：规则是隐藏）；
  给引线单独接一套 hover 弱化或抬层（它画在扇区自己的 `<g>` 里，两条链路自动覆盖，PIE-12）。

## API

```js
PieChart(host, {
  name,                     // 可选：这组数据的名字，tooltip 标题行（缺省不渲染标题行，PIE-05）
  items: [{ name, value }], // 扇区列表；null / ≤0 不占角（PIE-01）
  variant = 'donut',        // 'donut' 环 / 'pie' 饼 —— 形态语义，非样式参数
  legend = 'right',         // 'right' 左右结构 / 'bottom' 上下结构（PIE-09）—— 同上，形态语义
  platform = 'pc',          // 参与 behavior 解析
  dataLabel = 'auto',       // 'auto' 默认不出（LABEL-05）/ true 全开 / false 全关 —— 只管显隐
  labelLayout = 'outside',  // 'outside' 引线外侧（默认）/ 'inside' 扇区内（PIE-12 / PIE-04）—— 形态语义，互斥
  labelAlign = 'anchor',    // 'anchor' 就近 / 'column' 同侧成列 / 'edge' 贴边（PIE-13）—— 仅 outside 生效
  animation = true,         // 入场生长开关（MOTION-07）
})
```

颜色、半径、环宽、字号、间距一律走 token 与色板，API 一概不收（铁律4）。
