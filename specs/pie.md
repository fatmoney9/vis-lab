# 饼图 / 环形图 · 规范（条目化索引）

> 本页职责：给每条规则一个稳定 ID + 指向实现位置，供代码注释回引与修订检索。
> 适用范围：**无坐标系的占比图**——饼图（实心）与环形图（中空）。两者不按名字分体，而是
> 同一个 `PieChart` 的一个旋钮 `variant`（`'donut'` / `'pie'`），沿用 [bar.md](bar.md) 的先例：
> 变体是取值组合，不是两份组件。
> 分层：本族**新开一套 L2 骨架**（`charts/charts/pie/`），与 `CartesianChart` 平级、互不依赖——
> 它没有类目轴、没有值域刻度、没有网格，`scale` / `grid` / `axis` / `datazoom` / `crosshair`
> 整条 L1 链路都不适用；但**通用构件全部原样复用**：图例、数据标签、tooltip、水印、取色、
> 格式化、主题解析、画布骨架。本页只写「扇区自己的规则」，通用规则各回其家：
> 取色 → [color.md](color.md) COLOR-08 · 图例 → [legend.md](legend.md) · 标签 → [data-label.md](data-label.md) ·
> 浮层 → [tooltip.md](tooltip.md) · 动效 → [motion.md](motion.md) · 水印 → [watermark.md](watermark.md)。

## 扇区几何

| ID | 规则 | 实现 | 状态 |
|---|---|---|---|
| PIE-01 | **值 → 角度**：每扇区角 = `v / 可见项之和 × 360°`，**起始 12 点方向、顺时针**。<br>**`null` 与 `≤ 0` 不占角、不画**（与 [bar.md](bar.md) BAR-01「null 跳过」同口径）：占比是「对总量的份额」，负份额没有几何表达；`0` 也**不占位**——柱有 `size-zero-bar-placeholder` 1px 贴基线的表达，扇区的对应物是「0 角度」= 不存在，与 BAR-05 堆叠段「0 不占位」同口径。它们同样不进分母。<br>**绘制序 = 声明序 = 图例序，不按值排序**：排序会让同一实体在数据变化时换色，与 COLOR-04「颜色跟随实体、不跟随排名」直接冲突。<br>扇区间**无间隙**（`padAngle = 0`）、**无圆角** | `charts/charts/pie/geometry.js` → `sliceAngles()`；`charts/charts/pie/index.js` | ✅ |
| PIE-02 | **半径与环宽**：圆心 = 绘图区中心；<br>**外半径 `R = clamp(--size-donut-radius × 0.5, min(可用宽, 可用高) / 2, --size-donut-radius)`** —— token 是上限，空间不足时收缩（同 BAR-03 柱宽「上限 + 放不下就收缩」的口径），**但收缩有底：不小于该主题默认半径的 50%**（THS / iFinD-PC 70→35、Ainvest 80→40）。<br>**为什么要有下限**：没有它时容器越拖越小、环就一路缩到几像素——那时图例、标签、hover、水印全都还在，唯独「占比」这件本体看不见了，而它是这张图存在的全部理由。触底后容器继续变小，**环改为溢出画布**（`.dv-chart__plot > svg` 本就 `overflow: visible`），由调用方决定裁剪还是滚动：**「看得见但装不下」优于「装得下但看不清」**。<br>**取比例不取像素**：跟着各主题自己的 `--size-donut-radius` 走，故不进 token（同 BAR-03 柱与间距的 2:1、PIE-09 图例纵列的 ×2）。环宽因等比跟随而一并触底，环宽:半径比全程不变。**两种图例结构同一条规则**，不因方位分化。<br>⚠️ 与既有的「容器高 < 40px 就 `requestAnimationFrame` 重试」（本条末尾的 GRID-03 口径）**是两件事**：那道是「容器还没量出真高度」的等待，此处是「量出来了但太小」的下限，前者先于后者生效，故容器高跌破 40px 时图表停在上一帧、根本走不到下限判定。<br>**环宽等比跟随** `ring = --size-donut-ring-width × R / --size-donut-radius`，内半径 `innerR = R − ring`——收缩时保持本主题的环宽:半径比不变，与 BAR-02「柱与间距按同一比例等比缩小」同一先例。**尺寸按主题分化、比值不分化**：THS / iFinD-PC `70 / 28`、Ainvest `80 / 32`，两者的环宽:半径比都是 **0.4**，故等比收缩这条规则跨主题成立、L1 无需知道是哪个主题；<br>**`variant: 'pie'` → `innerR = 0`**（`ring` 不参与，退化为实心饼）；<br>**可用空间**：调用方明确给容器高度时按容器算，未给时用 `--size-donut-container`（三主题当前均 160px 方形）作默认包络，判定口径同 [axes.md](axes.md) GRID-03（`clientHeight >= 40`）。上下结构下还要先扣掉图例占位与间距，剩下的才是环可用的高。<br>**画布 = 图元的外接框，不留任何富余**——「图元」指环**以及圆外的引线与标签带**（PIE-12），无外侧标签时即退化为环的外接方框 `2R`。半径被 token 封顶后，多出来的画布**不会让环变大，只会变成图元与图例之间的死空间**，且随容器尺寸浮动，与 PIE-09「间距恒定」直接冲突。故画布尺寸由图元反推，而不是图元去适应画布。<br>**有外侧标签时**：宽 = `2 × 标签带 + 2R`（带宽**由容器反推、不看文本**，**两侧恒等**，PIE-13）、高 = `2 × max(R, 最外标签的 |y| + 块高/2)`（12 / 6 点方向的标签会探出环外）——**用「块高」不用「行高」**：`stacked` 档一个标签占上下两行，块高才是它真正占的纵向尺寸，且必须与 PIE-14 碰撞区间用的是同一个数（PIE-15）；**圆心恒等于画布中心**——带宽对称是为的就是这个，两侧不等宽会让环在卡片里明显偏向一侧。<br>**标签带是本条「不留富余」的例外，且是有意的**，两笔留白各有各的理由：① **带宽锚容器、不锚文本**——这是 PIE-13 切断「带宽 ⇄ 截断」那个环所付的代价，文本短时带内确实是空的，换来的是**环的大小与位置不随数据量、对齐档、名称长短跳动**；② **两侧恒等**——只有一侧挂标签时另一侧也留同宽的带，否则非对称带会把环整个推向另一侧，而环是这张图的视觉重心，它歪了整组「图 + 24px + 图例」就都歪了。带宽因此是**预留**而非外接，也正因为是预留才必须封顶（PIE-13 的 `--size-donut-label-band-max`）。<br>两个后果：① 可用空间必须从**图表根元素**量，不能从绘图区量（绘图区已贴着画布，拿它当输入会形成「画布依赖画布」的循环）；② 创建画布时要关掉 `createFrame` 的最小网格高（`minGridHeight: 0`）——那个下限是轴图的可读性兜底，对无轴图只会把画布重新抬高、再造出死空间。<br>**`--size-donut-container` 只是「高度」包络，不约束宽度**：它给的是组件未拿到显式高度时的默认高（口径同 cartesian 的 `size-chart-region-height`），半径由它定；宽度一律由图元反推。故 `容器 ≥ 2×半径 + 标签带` 这条从来不必成立——Ainvest 的 160 vs 2×80 不是冲突，标签带向外长出去即可。<br>饼图不另设尺寸 token，共用 `size-donut-*`（见待办） | `charts/charts/pie/geometry.js` → `donutRadii()`；`tokens/*.json §20` | ✅ |

## 图例布局

| ID | 规则 | 实现 | 状态 |
|---|---|---|---|
| PIE-09 | **饼环支持两种图例布局**，形态定义见 [legend.md](legend.md)——排布方向 LEGEND-01、方位 LEGEND-10、纵列溢出滑动 LEGEND-11；本条只定「支持哪几种、默认哪种、各自怎么配」：<br>· **`legend: 'right'` —— 左右结构（饼与环的共同默认）**：图左、图例右，图例纵向单列从上到下、左对齐，整列与绘图区垂直居中对齐。**默认不因 `variant` 分化**——饼和环都从左右结构起步。<br>· **`legend: 'bottom'` —— 上下结构**：图上、图例下，图例横向**居中**、行宽不足自动换行。<br>**不支持 `top`**：图例在上是直角坐标图的形态（LEGEND-04），饼环的设计源里没有这种排布。<br>**图与图例的间距 = `spacing-legend-chart-gap`（三主题 24px）**，两种结构共用同一个 token；图例朝向图那一侧的容器内边距（`spacing-legend-container-*`）清零，避免与之叠加成双份。**开着外侧标签时这 24px 从标签带外沿量起**，不是从环的外沿——标签带属于图元、已算进画布（PIE-02 / PIE-13），故这条规则不因标签形态而变，量的始终是「画布外沿 → 图例」。<br>**整组居中**：两种结构下绘图区都**不撑满剩余空间**，而是贴着图元的外接框成块（见 PIE-02：无外侧标签时是 `2R` 的正方形，有则加上两侧标签带），「图 + 间距 + 图例」作为一组在容器内居中——撑满的话图例会被推到容器边缘，且中间多出的空白随容器浮动，间距就不恒定了。左右结构把画布宽也显式传给 `createFrame`；上下结构只定高，宽度铺满、图元在其中水平居中即为整体居中（横向富余不夹在图元与图例之间，不影响间距）。<br>**由调用方按场景选**（宽扁卡片走 `right`、窄高卡片走 `bottom`），是「要哪种形态」的语义配置而非样式参数——同 `variant`，尺寸/间距/字号仍全走 token（WORKFLOW 铁律4）。**不进 `behavior.json`**：三主题同一套形态，不是主题分叉。<br>**左右结构下图例块与图元共享同一条水平中线**（容器拉高时两块一起居中，不是环居中、图例贴顶）：图例块走 `align-self: center`，**不能靠 flex 默认的 stretch**——本块另有 `max-height` 上限，**一旦上限生效，拉伸就被截断、flex 回退成 `flex-start`**，于是卡片一拉高环在正中、图例却贴着顶（实测卡片 1000px 时环心 y=468、图例块中心 y=140，差 328px）。改居中后其高度由内容决定，故 `max-height` 必须再与 `100%` 取紧者：stretch 时代「被容器压扁」天然不溢出，居中之后少了这道钳制，矮卡片里的图例会上下双向探出卡片。<br>**左右结构下图例纵列的高度上限 = 图元高度 × 2**，超出即在图例区内滑动（消费 [legend.md](legend.md) LEGEND-11 的「纵列溢出可滑动」——那条给的是**行为**，本条给的是**上限**）。不设限时图例会把整张卡片无限撑高（36 扇区能撑到上千像素，而环仍只有 2R），卡片高度就完全由图例说了算，与「图 + 图例相邻成一组」的观感背道而驰。**取比例不取像素**：它跟着图元大小走，换主题、换半径、开不开外侧标签都自洽，故不进 token（同 BAR-03 柱与间距的 2:1）。倍数在 L2 定、上限值写进一个自定义属性交给 CSS 表达；容器另有显式高度时两条约束同时生效、取更紧的那个。<br>**上下结构下图例块同样封顶 + 溢出滑动，但上限 = 默认图元高度 `--size-donut-radius × 2`**（THS / iFinD-PC 140、Ainvest 160）。与左右结构那条的两处差别都是有理由的：<br>· **锚在 token 上、不锚当前半径**——本结构下 `可用高 = 容器高 − 图例高 − gap`，**图例高反过来决定半径**；若上限再由半径算出，就成了「图例高 → 半径 → 图例上限 → 图例高」的循环。锚在一个与当前布局无关的常量上一刀切断：L2 首帧量到的就已经是封顶后的图例高，不需要二次重排、也不会出现首帧跳一下。**故本条纯 CSS 表达、L2 一行不参与**（左右结构仍走 `--dv-pie-legend-max-h`，两条各自的选择器只命中自己的结构，互不覆盖）。<br>· **倍数取 ×1 而非 ×2**——横排换行的图例是「铺开」的，占到与环等高就已经和环平分了卡片；纵列窄，所以才给到 ×2。<br>没有这条时窄卡片里 36 项能堆到 368px 高，把环挤到只剩下限半径（实测 240px 宽的卡片：封顶前图例要 368px，封顶后 140px、环回到满半径 70）。<br>**DOM 顺序恒为「绘图区 → 图例」**，方位只由容器 flex 方向切（LEGEND-10）——这与 `CartesianChart` 相反（那边图例 DOM 在前 = 在上），是本族唯一的骨架差异 | `charts/charts/pie/index.js`（DOM 顺序 + `.dv-chart--legend-*` 修饰类 + 推导 `layout`/`align`）；`core/legend.js` → `renderLegend()` 的 `layout` | ✅ |

| ID | 规则 | 实现 | 状态 |

  两段的颜色也分级：**名称段比数值段淡一级**（`color-text-secondary` vs `color-text-primary`，
  档③ LABEL-09），明暗切换时两级一起翻转。三主题都是**两个 `<text>`**（不是一段富文本），
  故 Ainvest 的引线指向两行之间、不偏向某一行。
- **超宽截断**（PIE-16，playground 的 **超长名称与数值** 那组）：名称被截成 `归属于母公司…`，
  **数值段恒完整**——截断的数字是错的数字。只有「连 1 字 + `…` 都放不下」或数值段自己就超宽时
  才整条丢（连引线一起，PIE-12 强绑定）。完整名称的兜底是 hover 扇区出气泡。
- **重叠即隐藏**（PIE-14）：外侧标签在数据量↑ 时**自上而下逐个消失**，且左右两栏各判各的
  （一侧密集不会牵连另一侧）；与柱线那条「超阈值整体消失」（LABEL-06①）形成对照——
  同一个 `dropCollisions`，一个判行、一个判列。
- **数据量 少 4 / 中 16 / 多 36**：36 扇区压色板循环（THS 扇区盘 11 色，循环到第 12 个扇区回到首色）；
  扇区数变化不改变动效节奏（MOTION-02）。开着标签时数据量↑可看它们按环宽 / 弧长逐个隐去（PIE-04）。
- **点图例**：隐藏一个扇区 → 剩余扇区重算闭合 360°，**其余扇区颜色一个都不变**（PIE-03 / COLOR-04 的验收点）；
  hover 图例项 → 其余扇区降到 `opacity-visualization-dim`。
- **hover 扇区**：三主题气泡**都走 follow**（与柱线示例的 THS `side-fixed` / Ainvest `top-anchor` 形成对照，
  这是 TOOLTIP-07 特例的验收点）；无指示线、无轴贴片。
- **命中面不止扇区面**（PIE-17）：开着引线档时，**hover 引线、名称段、数值段与 hover 扇区完全等效**——
  气泡、hover 外扩、点击常驻都一样（Ainvest 上最好验：任一处 hover，该扇区外径都从 80 变 90）。
  引线只有 1px，靠一条同点透明加粗的命中带才够得着；它整段都在环外，不会抢走扇区的命中
  （多 36 档逐点扫过整块画布，落在环面上的两千多个采样点被命中带截走 **0** 个）。
  切「扇区内」则相反：那档的标签仍是 `pointer-events:none`，指针落在字上命中的还是扇区本身。
- **入场动效**：顺时针扫掠，与同页柱线卡片**同时起跑同时到达**（MOTION-02）；关掉后与不带动效逐像素一致。
- **图例布局**（PIE-09）：两个示例都不带 `legend`，走组件默认的**左右结构**——
  图与图例相邻成组、**整组水平居中**，间距 24px；环形与饼图默认一致，不因 `variant` 分化。
  playground 右栏 **图例** 旋钮切 `上下` 可看另一种：图上、图例下横向居中换行。
  **图例永远在图之后**（DOM 与视觉都是），没有「图例在上」这一档——那是直角坐标图的形态。
- **旋钮显隐**：本族详情页**不出现**缩放轴 / 轴标题 / 渐变面积开关（`CHART_CAPABILITIES` 未声明），
  **也不出现直角坐标系那个「数据标签」开关**（`dataLabel` 能力本族未声明，显隐归标签形态管），
  只剩标签形态、标签对齐、图例布局与入场动效——这是两个预览面「按能力画旋钮」的验收点。
  反向对照：柱状图详情页有「数据标签」开关，却没有标签形态 / 标签对齐 / 图例布局这三个。
- **拖拽卡片改尺寸**（playground）：半径按 PIE-02 收缩、环宽等比跟随，环宽:半径比全程不变；
  **往小拖到底能看见下限**——THS / iFinD-PC 停在 R=35、Ainvest 停在 R=40 就不再缩，
  之后环溢出画布而不是继续变小（PIE-02）。**往大拖则验中线**：环与右侧图例块的中心
  在任意卡片高度下恒等（PIE-09），36 项时图例块自身封顶于图元高 ×2 后仍居中、内部滑动。

## Do / Don't

- ✅ **Do**：改环的尺寸与引线长度 = 改 `tokens/*.json §20` 的 `size-donut-*`（三主题同步，合同校验会拦）；
  改扇区取色 = 改 `tokens/palette.json` 或 [color.md](color.md) COLOR-08，不是给 API 加参数；
  新增的扇区专属几何留在 `charts/charts/pie/geometry.js`（标 `[L2-LOCAL]`）并保持纯函数可单测。
- ❌ **Don't**：把扇区几何下沉 `core/`（只有这一个 L2 用得上，WORKFLOW §三）；
  为「无坐标系图用 follow」给 `behavior.json` 加键（那不是主题分叉，见 PIE-05）；
  按值给扇区排序（COLOR-04）；用半径生长做入场（PIE-06）；
  给 API 加 `startAngle` / `padAngle` / `innerRadius` / 引线长度一类的样式参数（铁律4——
  `variant` / `labelLayout` / `labelAlign` 是形态语义，尺寸走 token）；
  把「放不下就不放」或碰撞贪心复制进 L2（通用规则在 `core/label.js` 内置，L2 只给分好栏的盒子——
  扇区内档另给 `maxWidth`，外侧档连它都不给（宽度已由 PIE-16 的截断保证，再复判一次反而会丢标签），
  **换个轴也是调用不是复制**，LABEL-06②）；
  为让外侧标签排得下而上下推挤它们（PIE-14 / LABEL-01：规则是隐藏）；
  给引线单独接一套 hover 弱化或抬层（它画在扇区自己的 `<g>` 里，两条链路自动覆盖，PIE-12）。

## API

```js
PieChart(host, {
  name,                     // 可选：这组数据的名字，tooltip 标题行（缺省不渲染标题行，PIE-05）
  items: [{ name, value }], // 扇区列表；null / ≤0 不占角（PIE-01）
  variant = 'donut',        // 'donut' 环 / 'pie' 饼 —— 形态语义，非样式参数
  legend = 'right',         // 'right' 左右结构 / 'bottom' 上下结构（PIE-09）—— 同上，形态语义
  platform = 'pc',          // 参与 behavior 解析
  dataLabel = 'auto',       // 'auto' 默认不出（LABEL-05）/ true 全开 / false 全关 —— 只管显隐
  labelLayout = 'outside',  // 'outside' 引线外侧（默认）/ 'inside' 扇区内（PIE-12 / PIE-04）—— 形态语义，互斥
  labelAlign = 'anchor',    // 'anchor' 就近 / 'column' 同侧成列 / 'edge' 贴边（PIE-13）—— 仅 outside 生效
  animation = true,         // 入场生长开关（MOTION-07）
})
```

颜色、半径、环宽、字号、间距一律走 token 与色板，API 一概不收（铁律4）。
