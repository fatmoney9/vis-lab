# 桑基图（SankeyChart）

> 规范来源：`vis-design-system` Skill 的 Sankey、Ainvest 与 THS 主题规范，以及收支拆解场景校准。
> 桑基图表达节点之间的流向与流量，不属于堆叠图表族。
>
> 状态表示当前实现与规则的符合程度：已通过逻辑校验与对应验收的规则标记为 ✅，
> 仍等待浏览器视觉验证的规则标记为 ⏳。

## 术语与语义

- **业务角色（role）**：节点在当前场景中的稳定语义，收支拆解使用 `income`、`expense`、`profit`。角色决定颜色，不由横向位置或数值正负号推断。
- **布局阶段（stage）**：节点在流程中的横向位置，由业务发生顺序或有向图深度决定。同一业务角色的节点可以出现在不同阶段。
- **有符号流量值（value）**：参与会计恒等式的原始数值，可以为正数、负数或零。符号表达贡献方向，不改变业务角色或链接方向。
- **几何量（magnitude）**：`abs(value)`。节点高度与边宽只使用几何量，避免负值消失或反向。
- **差额来源（negativeSource）**：财务差额为负时可声明的视觉来源兄弟节点，只改变负差额的出发位置，不改写参与守恒的逻辑 `source`。
- **终止节点**：没有后续流出的节点。终止节点可以出现在任意实际业务阶段，不等同于最右列节点。

数据必须显式声明无法从拓扑稳定判断的业务角色与阶段。渲染器不能凭“第几列”或“数值是否为负”猜测颜色。

## 布局与终止规则

### 自适应尺寸

桑基图没有统一的业务画板高度。`vis-design-system` 中通用的 160px，以及 Ainvest
覆盖的 200px，属于带 grid 的图表绘图区；无坐标系的 Sankey 不套用该高度。当前组件按节点规范推导：

- PC 绘图区最小高度为 `240 + 24 × 2 = 288px`，推荐绘图区为 384px，加图例后推荐总高为 424px。
- 移动端主节点为 120px，绘图区最小高度为 `120 + 24 × 2 = 168px`，推荐及最大可视绘图区为 203px，加 40px 图例后总高不超过 243px。
- PC 页面显式提供更高容器时使用可用高度；移动端节点密度所需高度更大时保持完整 SVG，并在 243px 可视画板内纵向滚动。
- 水平列距和标签槽不缩放；宽度不足时扩展 SVG，由页面承载区域提供横向滚动。
- 横版财报演示框固定高 375px，由 44px 标题区、243px 桑基可视区和 88px 播放操作区组成；最大可视宽度为 812px，窄屏只收缩可视宽度，三个纵向区段高度不变。

### 时间序列播放

- 播放轴只在相邻周期具有相同节点 ID 与 `source → target` 关系时使用平滑插值。
- 插值对象是链接的原始有符号值；节点高度、边宽与位置每帧重新布局，不对 SVG 路径字符串直接补间。
- 相邻周期均满足守恒时，线性插值的每个中间帧也满足守恒；格式化文字只用于展示。
- 切换周期时标题与数值文字立即显示目标期，保持当前几何 120ms；随后几何在 720ms 内使用通用 `cubicOut` 缓动，不对数字做计数动画。
- 播放轴只显示离散周期状态：切换开始时滑块立即跳到目标刻度，不沿轨道补间；图形仍独立使用缓动，暂停停留在当前几何中间态。
- 需要跨周期比较绝对规模时，各期必须共享同一个 `scaleMax`；最大期占满推荐主轴高度，其余期围绕画板中线等比收缩，禁止每期分别拉满后造成规模误读。
- 播放操作区参考 Figma `RviSlVW7lNx9BacoSApBA0 / 0:28082`：总高 88px，时间轴高 36px，白底描边滑块把手为 24×24px；下方播放键为 28×28px，上一期与下一期按钮均为 72×28px。宽屏刻度显示完整报告期，窄屏可缩写为“一季 / 半年 / 三季 / 年报”并保留完整无障碍名称；首尾分别贴齐轨道两端，1px 刻度线在横轴内垂直居中。
- 拓扑变化、切换至非时间序列场景或系统要求减少动态效果时，不播放过渡。

节点的横向位置按以下优先级确定：

1. 业务数据明确提供且通过有向关系校验的 `stage`。
2. 未提供 `stage` 时，根据有向无环图的拓扑深度推导。
3. 同一条边的目标阶段必须大于源阶段；不允许通过回折边伪造业务顺序。

终止节点只占用自身所在阶段。例如“营业收入 → 营业成本”在营业成本处结束时，营业成本应停在该阶段；它不需要与净利润、归母净利润等后续节点对齐，也不应把边带拉到图表最右侧。提前结束不会影响比例计算：营业成本收到的流量仍按全局比例尺决定节点高度与边宽。

## 流量守恒与数值显示

节点显示值由链接的有符号流量推导：

- 仅有流出的源节点：显示全部流出之和。
- 仅有流入的终止节点：显示全部流入之和。
- 同时有流入和流出的中间节点：有符号流入与有符号流出必须相等，显示该守恒值。
- 没有链接的孤立节点属于无效数据，不渲染。

每条边先使用 `abs(value)` 计算比例宽度，再应用 1px 的非零最小可见粗细；节点自身也至少显示为 1px。普通流量节点高度必须容纳其所有流入或流出的最终显示粗细之和。SANKEY-25 的财务负差额是显式例外：来源、成本与差额结果节点分别按自身值定高，来源到成本的主带允许变宽，差额带从成本超额段引出；若差额比例宽度不足 1px，只放大差额带本身，不改大成本节点。格式化后的单位（如“亿”“万”）只影响文案，不影响几何计算。若格式化后子项之和与父项文案存在尾差，应提高显示精度或标明“四舍五入”，不能改变边宽来迁就显示值。

## 节点标签

- 标签与对应节点保持紧邻，优先放在节点流向后的右侧。
- 默认第一行显示标题，第二行显示格式化数值。
- 标题使用当前主题正文色与 `font-family-cn` 系统字体，字号随节点高度在 10–12px 间线性变化。
- 数值优先使用 THS Money font / THSJinRongTi，无法加载时依次回退到 DIN Alternate 与等宽字体；该字体链仅属于桑基图。字号随节点高度在 11–14px 间线性变化。非负数值使用当前节点的语义色，负数值使用正文色。
- 标题显示宽度固定为 96px，不换行；超出后以省略号截断，并通过节点的可访问名称或 Tooltip 提供完整标题。
- 数值显示不截断：宽度超过 96px 时逐步缩小字号，最小 11px；11px 仍超宽时完整显示。全图标签槽宽度取 `max(96px, 最宽最终显示数值)`。
- 相邻布局阶段使用同一个水平列距：节点宽度、节点到标签的间距、全局标签槽宽度与列间留白共同决定列距。容器不足时扩展绘制区，不允许为适配容器而让各列使用不同间距。
- 容器边界或标签碰撞时可以将标签整体移到节点前侧，但标题与数值必须作为一个整体移动，不能失去与节点的对应关系。

| `ths` | `#FF9500` | `#3366FF` | `#FF2436` |

颜色由主题 token 提供，组件 API 不接收任意色值。图例文案属于业务语义，不等同于 token 名称：

| 语义角色 | 收支拆解推荐文案 | 说明 |
|---|---|---|
| `income` | 收入 | 收入、其他收益或其他正负贡献 |
| `expense` | 支出 | 成本、费用、税费等支出角色 |
| `profit` | 利润 | 毛利、营业利润、净利润等利润角色 |

图例顺序默认遵循“收入 → 支出 → 利润”；未使用某种颜色时不展示对应图例项。图例只解释业务角色颜色，不解释数值正负，也不参与筛选，除非业务另行定义可交互图例。

## 数据合同

以下为当前语义合同：

```js
SankeyChart(host, {
  platform: 'pc',
  nodes: [
    { id: 'business-income', name: '业务收入', role: 'income', stage: 0 },
    { id: 'operating-income', name: '营业收入', role: 'income', stage: 1 },
    {
      id: 'gross-profit',
      name: '毛利',
      role: 'profit',
      stage: 2,
      order: 1,
    },
    {
      id: 'operating-cost',
      name: '营业成本',
      role: 'expense',
      stage: 2,
      order: 0,
    },
  ],
  links: [
    { source: 'business-income', target: 'operating-income', value: 100 },
    { source: 'operating-income', target: 'operating-cost', value: 110 },
    { source: 'operating-income', target: 'gross-profit', value: -10 },
  ],
  legendLabels: {
    income: '收入',
    expense: '支出',
    profit: '利润',
  },
});
```

- `id`：稳定且唯一的节点标识；不应依赖可能重复或变化的展示名称。
- `name`：节点标题。
- `role`：取 `income`、`expense` 或 `profit`，表示稳定业务角色并决定节点颜色，与 `value` 的数值正负无关。
- `stage`：可选的非负整数，控制横向业务阶段；未提供时由拓扑深度推导。它不决定颜色。
- `order`：可选的有限数，控制同一阶段内的业务顺序；未提供时按角色分区、几何量与连线重心排序。
- `value`：有符号有限数。守恒计算使用原始值，几何计算使用其绝对值。
- `negativeSource`：可选的节点 ID / 名称，仅用于财务差额链接。负值时把视觉来源切换到同阶段兄弟节点的超额段；正值、零值及守恒计算仍使用原始 `source`。
- `legendLabels`：可选的三种业务图例文案映射，只改变文字，不改变颜色或布局。
- `platform`：`pc` 或 `mobile`，只控制边标签密度等端差异。
- 节点标题与节点值默认显示；边流量标签可以通过语义开关控制，并受移动端和密度策略约束。
- 主题与端：`ifind-pc` 仅用于 PC；iFinD 移动端直接使用 `ths` 主题，不存在独立的 iFinD-Mobile 桑基配置。
- 不接受颜色、节点宽度、间距、曲率或透明度等样式参数。

## 规范描述模板

描述一张桑基图时，应同时交代以下五类信息，不能只给节点名称和颜色截图：

1. **业务语义**：收入、支出、利润三种角色在当前场景分别代表什么，颜色不能随数值正负改变。
2. **阶段关系**：每个节点发生在哪个阶段，哪些分支会提前结束，哪些分支继续向右。
3. **守恒关系**：每个父节点的有符号值、子流量有符号之和、绝对值几何量、允许的显示尾差，以及真实差额如何建模。
4. **视觉编码**：三种语义角色分别使用哪个主题 token，边跟随目标节点色，所有几何共用全局比例尺。
5. **标签与图例**：96px 标题槽与长标题省略、分支高度驱动的双字号范围、长数值缩放与完整显示、负值文案颜色、图例文案和图例顺序。

推荐写法：

> 节点显式声明收入、支出或利润角色，颜色由角色决定，与数值正负无关。节点按实际业务阶段排列，终止分支停在发生阶段，侧向贡献从其真实阶段汇入主链。链接保留有符号值参与守恒，节点高度和边宽按绝对值共用全局比例尺；负值不反转链接，只在文案中显示负号并使用正文色。节点后显示标题与格式化数值，标题限定 96px 并在超长时省略；标题与数值字号随分支高度变化，长数值优先缩小、到最小字号后仍完整显示；全图以最宽最终显示数值或 96px 中的较大值统一列距。

不推荐只写“正数一种颜色、负数一种颜色”或“节点可以不到最后”。这类表述混淆了业务角色与数值符号，也没有说明提前终止后的比例、守恒、标签和图例如何处理。

## 验收检查清单

- [ ] 每个节点都声明了 `income`、`expense` 或 `profit`，不由列位置或数值符号猜测。
- [ ] 正负值都保持业务定义的链接方向与角色颜色，负值文案显示负号并使用正文色。
- [ ] 每种实际使用的语义色都有一个图例项，颜色、文案与节点一致。
- [ ] 提前结束的分支停在实际阶段，没有空节点、虚拟节点或延长边。
- [ ] 所有边宽与节点高共用同一个绝对值比例尺，有符号父子流量守恒。
- [ ] 节点与非零小流量至少显示为 1px；普通节点容纳最终边宽，财务负差额节点保持值比例并通过变宽主带与超额回弯承接差异。
- [ ] 节点标题与数值成组显示，非负数值跟随角色色，负数值使用正文色。
- [ ] 相邻阶段列距一致；标签槽不小于 96px，并能容纳全图最宽的最终显示数值。
- [ ] 首层分叉自然展开，后续节点逐级向画板中轴回拉，主链不随中间业务节点漂移。
- [ ] PC 每列上下节点至少间隔 24px，移动端至少 12px；双节点与三节点范围按端侧主节点尺寸区分。
- [ ] 无显式高度时 PC 总高采用 424px；移动端可视总高不超过 243px，密集数据在画板内部纵向滚动。
- [ ] 同拓扑季度播放时标题和数值先切换，几何随后平滑变化；滑块离散跳到目标刻度，暂停、刻度拖动、上一期、下一期和减少动态效果均可用。
- [ ] 跨周期比较使用统一 `scaleMax`，最大期主轴满高，其他期按值缩放且始终以画板中线为中心。
- [ ] 毛利等财务差额为正时从原始来源分出，为负时从声明的成本超额段回弯引出；Hover 关系跟随当前视觉来源。

- [ ] 标题使用系统字体和 10–12px 动态字号，限制为 96px，超长单行省略且仍可访问完整文本。
- [ ] 数值使用 THS 金融数字字体和 11–14px 动态字号；超宽时缩小，到 11px 后仍完整展示。
- [ ] THS 金融体不可用时回退到 DIN Alternate，DIN 不可用时回退到等宽字体，且不改变其他图表。
- [ ] 格式化与四舍五入只影响文字，不改变几何比例。
- [ ] Hover / 聚焦 / 点击节点时单行看板完整，点击可保持；边只高亮且不出看板，细边命中稳定。
- [ ] Hover、键盘聚焦、密集节点和长标题状态均可读、可访问。

## Do / Don't

- Do：至少提供一条完整的多阶段路径，并明确业务角色与布局阶段。
- Do：对每个节点声明 `role`，让收入、支出与利润稳定着色。
- Do：让终止分支停在实际业务阶段，让侧向贡献从真实阶段汇入，并保持有符号流量守恒。
- Do：为非零小流量应用统一的最小可见粗细；普通节点按最终粗细扩高，财务负差额节点保持自身值比例。
- Do：以全图最宽最终显示数值和 96px 标题宽度共同确定统一列距。
- Do：根据节点最终显示高度映射标题与数值字号，长数值先缩字号、到下限后完整显示。
- Do：为每种实际使用的语义色提供一个清晰的业务图例。
- Do：节点超过 30 个时保留完整数据并让绘制区自适应扩展；如需提升阅读效率，由业务显式提供聚合、筛选或分页入口。
- Don't：不要传 `stack`，也不要把多组序列先堆叠后转换为节点。
- Don't：不要用数值符号推断业务角色，也不要反转或隐藏负值边；不要使用渐变边、等宽边或按系列循环配色。
- Don't：不要把最小可见粗细换算回业务值，也不要让放大后的细边溢出节点。
- Don't：不要把所有终止节点强制拉到最右列，也不要通过空节点或虚拟边补齐。
- Don't：不要为视觉对齐静默缩放单条边，或用格式化后的展示值参与几何计算。
- Don't：不要省略节点数值、让数值颜色脱离节点语义色，或为同色节点重复创建图例。
- Don't：不要按单个节点的短标题或短数值分别压缩列距，也不要让超长标题撑开列距。
- Don't：不要因为节点数超过建议阈值就拒绝渲染、截断数据或自动合并节点。
